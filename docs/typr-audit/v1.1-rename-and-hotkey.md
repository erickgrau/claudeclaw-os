# Mabel v1.1: rename + configurable hotkey

Builds on top of `v1-security-pass`. Two unrelated changes shipped in one
patch since neither is big enough to warrant its own.

## Rename Typr → Mabel

User-facing rename only. The repo can stay named `typr` (rename it later if
you want); this patch only touches in-code identifiers.

| Field | Was | Now |
|-------|-----|-----|
| `productName` (tauri.conf.json) | Typr | Mabel |
| `identifier` (tauri.conf.json) | com.typr.app | com.mabel.app |
| Window title | Typr | Mabel |
| App data dir | `~/Library/Application Support/com.typr.app/` | `~/Library/Application Support/com.mabel.app/` |
| Cargo crate name | typr | mabel |
| Cargo lib name | typr_lib | mabel_lib |
| npm package name | typr | mabel |
| Log prefix in stdout | `[Typr]` | `[Mabel]` |
| Keychain service name | com.typr.app | com.mabel.app |
| Sidebar app name | Typr | Mabel |

Side effect: changing the `identifier` changes the app data directory. Any
existing Typr install loses its config and downloaded models on first launch
of the renamed build. Acceptable since nobody's running it in production yet.

## Configurable global hotkey

Before: hotkey was fixed to whatever was in `config.json` at app start.
Changing it required quitting, editing the file by hand, and relaunching.

After: click the hotkey kbd in Settings → Recording, press the combination you
want, and it rebinds live.

### Backend (`src-tauri/src/main.rs`)

- Extracted the inlined shortcut handler closure into `build_shortcut_handler(handle)`,
  a function that returns a fresh closure with the same body. Lets us register
  the same handler under different shortcuts without duplicating ~50 lines.
- New Tauri command `update_hotkey(hotkey: String)`:
  1. Returns early if unchanged or empty.
  2. Unregisters the previous binding.
  3. Calls `on_shortcut(new, build_shortcut_handler(...))`.
  4. On success: persists to settings via `Settings::save`.
  5. On failure: re-registers the old binding so the app stays functional,
     returns the error to the frontend.
- Wired `update_hotkey` into the `invoke_handler` list.

### Frontend (`src/main.ts`)

- New `eventToAccelerator(KeyboardEvent)` builds a Tauri-format accelerator
  string ("CmdOrCtrl+Shift+Space") from a JS keyboard event. Maps `e.code`
  values like `KeyA`, `Digit1`, `Space`, `Enter`, `Arrow*`, `F1`-`F19`,
  punctuation, etc.
- Refuses to bind a bare letter without a modifier (would steal every
  keystroke globally). Function keys are exempt.
- Click handler on `#hotkey-text`:
  - Adds `.capturing` class for visual feedback.
  - Listens at `keydown` (capture phase) on document.
  - Esc cancels with no change.
  - Any usable combo invokes `update_hotkey` and updates the display on
    success, reverts on failure.

### CSS (`src/style.css`)

- `kbd` becomes `cursor: pointer`, hoverable, focusable.
- `.capturing` state pulses with the accent color so it's obvious the app is
  listening for keys.

### HTML (`index.html`)

- Hint text changed from "Global keyboard shortcut to trigger recording" to
  "Click to rebind. Press Esc to cancel."
- `tabindex="0"` on the kbd so it can also be activated via keyboard.

## What's NOT in this patch

- Conflict detection (e.g. checking if Cmd+Q would swallow Quit). Tauri's
  `on_shortcut` will reject combinations that conflict with system bindings,
  and the frontend surfaces that error in an alert.
- Right-click menu to reset to default. Easy add later if needed.
- Multiple hotkeys (e.g. one for toggle, another for PTT). Single hotkey only.
